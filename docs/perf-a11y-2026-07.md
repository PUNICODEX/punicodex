## 2. Static performance audit (6 key pages)

Above-fold = resources fetched before first scroll on a desktop viewport.
Weights are on-disk; webp is what modern browsers actually transfer.

| Page | Above-fold images | Hero policy | Notes |
|---|---|---|---|
| `/` | ~44 KB (nav lockup 12 KB webp + emblem 16 KB + hero knot 16 KB webp `fetchpriority="high"`) | hero high-priority, knot-square variants `lazy`, 204 KB mp4 loop `preload="none"` with webp poster | Clean. 7 render-blocking stylesheets (all site CSS, self-hosted fonts, preloads for main/home CSS + 2 woff2) |
| `/pantheon/` | ~28 KB (nav 12 KB + council-of-twelve 16 KB webp `fetchpriority="high"`) | correct | Clean |
| `/tiers/` | ~28 KB (nav 12 KB + triad-ziggurat 16 KB webp `fetchpriority="high"`); tier seals 68–76 KB PNG are `lazy` | correct | Clean |
| `/type/` | ~20 KB (nav 12 KB + monolith 8 KB webp `fetchpriority="high"`) | correct | `type/js/lexicon.js` is 1.03 MB but `defer`red and is the app's data — expected |
| `/about/` | ~12 KB (nav only; spark-eclipse 8 KB webp is `lazy` below fold) | correct | Clean |
| `/sites/zeus/` (via `templates/flagship/index.html` + `scripts/create-flagship.js`) | ~826 KB (nav logolockup 193 KB webp + hero mascot **633 KB webp** / 2.9 MB PNG fallback) | **mascot had no fetchpriority/decoding — FIXED** | mascot is the LCP candidate; portal-ring decorative img is `lazy` + `aria-hidden` + `pointer-events:none` ✓ |

### Perf findings and fixes

1. **Flagship hero mascot (LCP) had no priority hints.** Every flagship home
   tab renders `{id}_mascot.webp` as its largest above-fold element
   (zeus: 633 KB webp; heavy end of the fleet) with default priority.
   Fix: `fetchpriority="high" decoding="async"` added in
   `scripts/create-flagship.js:932` (`buildHeroVisual`) and
   `scripts/create-flagship.js:1570` (`buildHeroVisualExtended`).
   `convert-images-to-webp.js` does not clobber this — its lazy list
   (`LAZY_LOAD_CLASSES`) does not include `patron-mascot-img`/`mascot-img`,
   and it only *adds* attributes when absent.
2. **`px-core.js` was parser-blocking on 3 of 6 audited pages** while
   `defer`red on the others. `index.html:480`, `tiers/index.html:515`,
   `about/index.html:208` now match (`defer`). Impact is small (the tag sits
   at end of body); this is consistency + guaranteed non-blocking.
3. **No unexpectedly large assets on root pages.** No `/assets/brand/` file
   exceeds 400 KB (checked webp + png). The only >500 KB asset on any audited
   page is the zeus mascot webp (633 KB) — a per-temple generated asset, see
   Risks.
4. **Caching headers** (`vercel.json`, read-only review): `/css`, `/js`,
   `/assets` are `public, max-age=31536000, immutable`; HTML and service
   workers are `must-revalidate`. Correct for the fingerprinted
   `?v=perfN` strategy.
5. **Not changed (deliberately):** end-of-body scripts on flagship templates
   (`flagship-canvas.js` 107 KB etc.) were left synchronous — an inline
   booking script follows them and execution order with `defer` would change
   risk for zero render gain at end of body.

## 3. Accessibility audit of the new brand elements

**(a) alt on new `<img>`/`<picture>`** — full scan of the brand-owned
canonical files (all root pages, 9 flagship templates, 11 scholars pages,
mobile/extension HTML, `js/pantheon.js`, `js/home.js`, `portal.js`,
`create-flagship.js`, `generate-temples.js`, both fixer scripts): every
`<img>` has `alt`. Decorative images (hero emblem, empty-portrait fallback,
portal-ring) correctly use `alt=""`; meaningful art carries descriptions.
Guard: brand test (o).

**(b) icon-only image links** — `.nav-wordmark`, `.footer-wordmark`
(alt "PuniCodex — The Unicode Pantheon"), `.global-brand` and `.nav-logo`
in temples (alt "PuniCodex" / the entry's Unicode name) all resolve an
accessible name from the img alt. `a.cn-logo-row` on search was the one
failure (mismatched overriding aria-label) — fixed, see (u).

**(c) Gold-on-obsidian contrast — computed WCAG ratios** (sRGB linearization,
`L = 0.2126R + 0.7152G + 0.0722B`, ratio = `(L1+0.05)/(L2+0.05)`):

| Foreground | Background | Ratio | Use | Verdict |
|---|---|---|---|---|
| `#D4AF37` (--pc-gold) | `#0A0A0C` (--pc-obsidian) | **9.41:1** | kickers, pills, ghost buttons, tier chips (body sizes) | AA/AAA pass (≥4.5) |
| `#D4AF37` | `#050505` (--void, main.css) | 9.69:1 | main.css pages | pass |
| `#D4AF37` | `#121216` (temple-black cards) | 8.89:1 | text on cards | pass |
| `#F5E3A8` (gold-highlight) | `#0A0A0C` | 15.48:1 | gradient text top | pass |
| `#C9A23F` (gold-mid) | `#0A0A0C` | 8.22:1 | gradient text middle | pass |
| `#8C6A22` (gold-deep) | `#0A0A0C` | 3.96:1 | **only** the base of the `.pc-display` gradient at display sizes (≥36 px) | passes 3:1 large-text; would fail body text — not used for body text |
| `#9A968C` (--pc-ash) | `#0A0A0C` | 6.70:1 | secondary text | pass |
| `#6B685F` (--pc-ash-dim) | `#0A0A0C` | 3.55:1 | "tertiary text, captions" per token comment — **currently unused in any stylesheet** | would fail AA if adopted for text — see Risks |
| `#F4EFE4` (--pc-ivory) | `#0A0A0C` | 17.25:1 | primary text | pass |

No body-sized text anywhere uses a failing gold. Guard: brand test (s).

**(d) Focus visibility** — neither `css/main.css` nor `css/temple-base.css`
had any `:focus-visible` rule, so the new image links relied on the UA
default ring. Added an on-brand `2px solid` gold outline: `css/main.css:1268`
(all root pages) and `css/temple-base.css:2863` (all 895 temples). The new
pantheon pills also have an explicit `:focus-visible` rule.

**(e) Stamp/medallion overlays** — `.card-portrait::after` (medallion frame)
and `.archetype-card.unbuilt .card-portrait::before` (awaiting-restoration
stamp) in `css/pantheon.css` / `css/home-v2.css`, plus
`.gallery-figure::after` in the gallery template: all are pseudo-elements
with `content: ''` (no text) and `pointer-events: none`. Pseudo-elements with
empty content never enter the accessibility tree — confirmed fine. Guard:
brand test (p) now pins both properties.

## 6. Remaining risks / follow-ups

1. **Per-temple mascot weight.** `sites/{id}/assets/{id}_mascot.webp` runs
   ~190–630 KB (zeus 633 KB, logolockup 193 KB). Fleet-wide re-encode at a
   lower quality/width would cut LCP on flagship pages; it is a generated
   asset, so the fix belongs in the asset pipeline, not in `sites/`.
2. **`--pc-ash-dim` (#6B685F, 3.55:1) and `--pc-gold-deep` (#8C6A22, 3.96:1)**
   would fail AA if ever adopted for body-sized text. Both are currently used
   only as documented (unused / display-gradient base). The tokens were left
   untouched to stay faithful to the brand kit; brand test (s) guards the
   values that carry text today. Same caution for main.css `--text-dim`
   (#555555, 1.6:1 on `--void`) — still used for decorative icons and muted
   text in `css/main.css:684`/`:943`; any future text use there needs the
   same swap this pass applied to the pantheon stats-bar.
3. **Root `.mobile-menu` (non-temple) links** remain tabbable while the menu
   is closed (no aria-hidden/inert there). Not Lighthouse-flagged; the
   px-core sync intentionally only manages menus that declare
   `aria-hidden`. Worth a follow-up sweep of the root menu markup.
4. **Pantheon CLS 0.182** (JS-rendered card grid) — under the gate but the
   largest layout-shift source on the sampled root pages.
5. **sites/* re-verification** — after `npm run generate`, the flagship
   pages should be re-audited to confirm `aria-hidden-focus` and
   `heading-order` are gone fleet-wide (templates verified statically here).
