# PuniCodex Lighthouse Reports

This directory holds the latest Lighthouse reports for a representative sample of
public pages. Reports are generated by `scripts/run-lighthouse.js`.

## Running the audit

```bash
node scripts/run-lighthouse.js
node --test test/lighthouse.test.js
```

The runner starts a local static server on `127.0.0.1:3000`, audits each page
with the **desktop** preset, and writes:

- `docs/lighthouse/{slug}-{date}.json` — full Lighthouse JSON report
- `docs/lighthouse/{slug}-{date}.html` — rendered HTML report
- `docs/lighthouse/summary-{date}.json` — score summary for all sample pages

- Performance

## Known shortfalls

The following pages fall below the 90 target on at least one category. The
blockers are intrinsic to the requested product surface and were not removed per
the Phase 5 constraint that hero effects, canvas scripts, and bespoke animations
must be preserved.

- **pantheon — Performance 86**
  - Large pantheon grid with many cards and images increases LCP/CLS.
  - Hero canvas animation is preserved.

- **lexicon — Performance 84**
  - 860-entry searchable/filterable grid renders a large DOM.
  - Full lexicon dataset is loaded client-side to power instant filtering.

- **type — Accessibility 87**
  - Interactive type-tool keyboard and custom controls require additional ARIA
    refinement for a perfect score.
  - No functionality was removed.

## Notes

- Best Practices is capped at 96 on all pages because the local static server
  does not serve with HTTPS/HSTS/HTTP2, which are expected only in production.
- Hero canvas effects are intentionally preserved; they are the primary visual
  identity of flagship temples.
