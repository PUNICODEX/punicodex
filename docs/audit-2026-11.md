## 1. Connections — the real gaps

### 1a. 293 of 548 flagships are not in the connections graph at all

`platform/api/similarities.json` nodes cover only **255 of 548** flagships.
Missing names include some of the biggest in the lexicon:

- **Greek**: Hēra, Hestía, Athēnai (the city), Okeanos, Apsū, Tártaros, Ánankē's peers…
- **Egyptian**: Ḥor, Hekā, Māꜥ, Ákh, Ab, Bꜣ, Kꜣ (the soul-parts!), Shū
- **Norse**: Álfheimr, Helheimr, Jǫtunheimr, Miðgarðr, Muspellheimr, Ragnarǫk
- **Canaanite/Phoenician**: ʿAštart, Ḥōr's Levantine kin
- **Mesopotamian**: Anu, Apsu
- **Sanskrit**: Prajāpati, Ṛta, Vāc, Om
- **Greek locations**: Aígyptos, Asía, Evrópē's siblings, Kṑbe, Kyōto, Ōsaka, Spártē, Ólympos

Every flagship archetype should carry at least 2–3 similarity edges (cognate,
cognate-of-domain, kinship, or same-concept). The generator
(`scripts/generate-similarities.js`) draws on lexicon variants + cognates; these
293 need edges authored or derived (many have variants/cognates already in the
lexicon — the wiring just doesn't exist).

## 2. SEO audit (gold standard)

What already meets the bar (verified by the SEO suites): unique titles/
descriptions per page, canonical links sitewide, JSON-LD (980 temples as
schema.org/ProfilePage-ish structures + CollectionPage/Product on the store),
clean URL canonicalization (middleware 301s + .html collapse), sitemap
(14,863 URLs, image entries, no noindexed conflicts), robots.txt discipline,
self-hosted fonts, OG/Twitter cards, breadcrumbs with BreadcrumbList,
mobile viewport + responsive suites, Lighthouse ≥90 gate, accessibility sweep.

Gaps found / recommended, in priority order:

1. **Competitor-scale content depth per flagship.** Mythopedia's entries run
   1,500–3,000 words with citations. Our flagship temples have lore + blog +
   scholars tabs, but the main temple body should present the
   "story-first" long-form section (600–900 words) above the fold data to
   compete for informational queries ("who is X in mythology"). The Scholarly
   Edition content is the raw material — surface a teaser + link.
2. **FAQ structured data.** Add FAQPage JSON-LD to flagship temples (3–5
   questions: pronunciation, meaning, variants, domain) — the pronunciation
   engine can generate these deterministically.
3. **HowTo on /type/ and /ink/.** Both are procedure pages; HowTo schema
   wins SERP real estate.
4. **BreadcrumbList on /store/merch/* deep pages** exists — extend to
   /store/art/galleries/ sections (ItemList with anchors is present; add
   BreadcrumbList + the temple anchors).
5. **Image SEO**: galleries images have alt + captions now — add
   `figcapture`→`caption` schema (ImageObject with license via
   `acquireLicensePage` — we already hold the Commons license metadata).
   This also feeds Google Images with licensable badges — a differentiator.
6. **Video schema**: herald/edition videos + temple hero videos should carry
   VideoObject (name, description, thumbnailUrl, uploadDate).
7. **Site search sitelinks**: a `/search/` page + SearchAction in the
   WebSite JSON-LD on the home page enables the sitelinks search box.
8. **E-E-A-T surface**: the founder page + citations + the university
   program are strong; add `author` + `reviewedBy` Person schema on codex
   essays (they're the credibility long-tail).
9. **Performance budgets**: hero canvases are DPR-capped; add `<link
   rel="preload">` for the two hero fonts on temple pages (only Cormorant
   is preloaded now on some templates).
10. **Hreflang**: single-language for now; when the app strings localize,
    plan hreflang from day one (the app already ships 70+ locales — the site
    should follow).

### Competitor posture (do NOT copy — outcompete)

- **Mythopedia**: strength = long-form scholarship + clean IA. Weakness = no
  interactive layer, no original-language depth, thin on non-Greco-Roman.
  We beat them on: original scripts, pronunciation engine, the type tool,
  live Unicode domains, the game/cards ecosystem, and pantheon breadth (25
  vs their ~12). Gap to close: entry-level word count + citation density.
- **Theoi**: strength = primary-source citations per fact. Weakness = UX from
  another era, English-only. We beat them on experience and languages; keep
  the Scholars Edition as our citation engine and expose it more visibly.
- **Ancient History Encyclopedia / World History Encyclopedia**: strength =
  general-audience reach, video. Weakness = mythology is a side dish. Our
  niche dominance + their general SEO = our encyclopedia-style "codex" essays
  should target their long-tail ("Greek god of war" → our rulebook-grade
  accuracy with tools they don't have).
- **Whale watch**: WHE's domain authority is the whale. Do not fight
  head-on; own the queries they can't: Unicode names, punycode, "how do you
  spell", tattoo verification, domain availability — the tool-backed queries.

## 3. Deployment process — fresh-agent critique

Honest read of the repo as a new agent would experience it:

**What is now straightforward:**
- AGENTS.md states the shipping rule plainly (full generate → test → generate
  → commit together → push).
- `generate:check` is now a CI-mirror: any tracked drift vs HEAD fails. A new
  agent can trust a green local check to mean a green CI gate.
- evolve is clearly labeled as non-gating (nightly gardener).

**What would still trip a fresh agent (fix or document):**
1. **Windows vs CI divergence traps**: whole-tree injectors take seconds on
   Linux CI but can crawl under Windows Defender; a fresh agent on Windows
   may think the pipeline is "hung". Document: run generates solo, expect
   10–20 min, watch Task Manager for competing node processes.
2. **Pin discipline is scattered**: `asset-pins.js` + inline `?v=` strings in
   generators + content-stamped hashes. A new agent must know: any css/js
   change → bump `asset-pins.js` AND the inline literals (there is a test
   suite guarding some, not all). Consolidate into one helper.
3. **The battery rewrites the tree** — surprising but documented now; still,
   a `npm test` followed by `git status` showing 7k modified files will
   panic a newcomer. Consider a post-test convergence hook.
4. **Native modules**: the better-sqlite3 ABI incident shows native deps can
   break silently per-platform. The engines pin (`22.x`) + deploy build
   alignment fixed it; document *why* engines is load-bearing.
5. **vercel.json is treacherous** (as AGENTS.md says) — the test guarding it
   is the only thing between an agent and a routing outage. Good as-is; make
   the guardrail comment louder at the top of vercel.json itself.

Verdict: after the 2026-11-02 process fixes, a fresh agent following
AGENTS.md would deploy cleanly. The remaining rough edges are documentation
placement, not process.
