# PuniCodex URL / Canonical Architecture Map
Read-only investigation, 2026-08-21. Branch master @ d7686e45. Lexicon: 966 entries, 287 flagships.

## 1. Middleware (`middleware.js`, 1458 lines)

### Generated domain block
- `DOMAIN_MAP` (lines 5–1304): GENERATED by `scripts/sync-middleware-domains.js` from `js/archetypes-v2.js`; maps each owned Unicode/punycode domain → `/sites/{id}`.
- `DOMAIN_TO_ID` reverse map built at lines 1307–1311.
- **`ARCHETYPE_IDS` (line 1314)**:
  ```js
  const ARCHETYPE_IDS = new Set(Object.values(DOMAIN_MAP).map(p => p.replace('/sites/', '')));
  ```
  → exactly the ~287 flagship ids (only ids with an owned domain in the archetype list). Base-temple ids are NOT in the set.
- `LEGACY_REDIRECTS` (1317–1321): `/aether→/aither`, `/enki→/ea`, `/oceanus→/okeanos`.
- `config.matcher` (1327): `'/((?!api/v1/scholars/).*)'` — middleware does NOT run on `/api/v1/scholars/*`.

### Request pipeline (`middleware()` from line 1330)
1. **API trailing-slash fix (1338–1342)**: no-trailing-slash `/api/*` calls are internally rewritten to the slash version (avoids Vercel's 308 from `trailingSlash:true` breaking CORS preflight).
2. `/api/*` pass-through (1345–1347).
3. **Defensive domains (1356–1366)**: `punycodex.com`, `www.punycodex.com`, `www.punicodex.com` → 301 to `punicodex.com` (path preserved).
4. **DIRECT_SERVE_MAP (1371–1388)**: `helheimr.com`/`www.helheimr.com` serve the temple directly (no redirect): `/js/`, `/css/`, `/assets/fonts|brand/` fetched from root, everything else internally prefixed to `/sites/helheimr`.
5. **EXTERNAL_REDIRECT_DOMAINS (1393–1411)**: `νίκη.com`/`xn--kxaqik.com` (+www) → 301 `https://punicodex.com/nike` + path + query.
6. **Deity-domain 301 (1413–1426)**:
   ```js
   const id = DOMAIN_TO_ID[host];
   if (id) {
     url.hostname = 'punicodex.com';
     url.pathname = '/' + id + url.pathname;
     return new Response(null, { status: 301, headers: { Location: url.toString(), ... } });
   }
   ```
   So every deity domain 301s to the **clean** `/{id}/` form, never to `/sites/{id}/`.
7. **Legacy path 301s (1430–1441)**.
8. **Archetype clean-URL rewrite (1443–1455)**:
   ```js
   const pathParts = url.pathname.split('/').filter(Boolean);
   const potentialId = pathParts[0];
   if (ARCHETYPE_IDS.has(potentialId)) {
     const prefix = '/' + potentialId;
     if (url.pathname === prefix || url.pathname.startsWith(prefix + '/')) {
       url.pathname = '/sites' + url.pathname;
       return fetch(url);
     }
   }
   return fetch(request);
   ```
   `/{id}` and `/{id}/*` internally serve `/sites/{id}*` — the URL bar keeps the clean form. Non-archetype first segments (incl. base-temple ids like `marduk`) fall through to `fetch(request)` → static filesystem → **404**.
9. **`/{id}/assets/*`**: no special middleware branch — the rewrite in step 8 turns it into `/sites/{id}/assets/*`, which then hits the vercel.json proxy rewrite (see §6). The DIRECT_SERVE_MAP block (1377–1385) explicitly refuses to blanket-allow `/assets/` for this reason.
10. **Trailing slash**: no page-path slash logic in middleware; `vercel.json` `trailingSlash:true` issues a 308 `/x` → `/x/` before/around middleware.

## 3. Internal links — which form?

**Everything crawlable links to `/sites/{id}/`.** Nothing links to `/{id}/` directly (it only receives 301s from deity domains).

- Flagship templates: tab nav is relative (`href="lore/index.html"`, `templates/flagship/index.html:105` etc.), but breadcrumbs/related cards are absolute `https://punicodex.com/sites/{{TEMPLE_ID}}/` (`blog/index.html:153`, `scholars/index.html:265`). JSON-LD url `/sites/` form (`index.html:33`).
- Base temples: related/cognate cards absolute — `scripts/generate-temples.js:497` (`https://punicodex.com/sites/${c.id}[/lore/]`), `:1123`, `:1157`.
- Flagship generator: `scripts/create-flagship.js:3319` → `/sites/${member.id}/patterns/` etc.; one legacy relative helper at `:1549` (`../../${e.id}/` — resolves to `/{id}/` from a `/sites/{id}/` base, an accidental clean-URL leak).
- Hub index blocks: `scripts/sync-temple-index.js:66` → `` `<li><a href="/sites/${entry.id}/">` `` injected into `lexicon/`, `pantheon/`, `pronunciation/`, `tiers/` (targets at lines 38–41).
- `lexicon/index.html` JSON-LD ItemList: `"url": "https://punicodex.com/sites/{id}/"` (line 90+, generated by `scripts/generate-itemlist-schemas.js`).
- `realms/index.html`: static cards `href="/sites/{id}/"`.
- JS renderers: `js/connections.js:494,507`, `js/home.js:20–22`, `js/ink.js:151,283,352`, `js/pantheon.js:44`, `js/trending-temple.js:63` — all `/sites/`.
- `scripts/generate-everyday-page.js:85` → `/sites/${entry.id}/`.
- Deity-domain buttons on temples link to `https://{deity-domain}` which 301 → `/{id}/` (indirect signal only).

## 5. 404 sources

- **`/media`**: no `href="/media"` anywhere. Only JS API calls `api('/media')` with `apiBase = '/api/v1/scholars'` (`platform/public/scholars/institution/index.html:788,1590`; `templates/flagship/scholars/index.html:626` baked into all 287 `sites/{id}/scholars/` pages) — real target `/api/v1/scholars/media`. Also route paths in `platform/scholars/router.js:1495,1560`. Google likely picked up the relative string from rendered JS. Not robots-disallowed.
- **`/auth/session`**: same pattern — `api('/auth/session')` in `platform/public/schola
rs/{admin,dashboard,dept-admin,institution,review}/index.html` and in the flagship scholars template (`templates/flagship/scholars/index.html:355`, apiBase at :317) — baked into 307+ `sites/*/scholars/index.html` files. No file at `/auth/session` → 404 when fetched bare.
- **`/api/v1/scholars/`**: excluded from middleware (matcher, line 1327); vercel.json rewrites (24–30) send it to the handler; bare GET 404s. Reachable as text/links from `/api/v1/docs/` (Swagger). **`robots.txt` disallows only `/api/admin/`, `/admin.html`, `/platform/`** — the rest of `/api/` is crawlable.
- **`/marduk/`, `/korinthos/`**: base-temple ids not in ARCHETYPE_IDS → middleware falls through → no static dir at root → 404 (see section 7). Both exist at `sites/marduk/index.html`, `sites/korinthos/index.html`.
- **`robots.txt`** (root, 11 lines): `Allow: /`; disallows the three above; `Crawl-delay: 1`; sitemap line. `/account/` and `/admin-portal/` deliberately NOT disallowed (they carry noindex; comment lines 6–8).

## 6. vercel.json
- `"trailingSlash": true` (line 2), `"cleanUrls": true` (line 3). **No `redirects` key.**
- First rewrite (11–14): `/sites/:path*/assets/:file*` → `https://punycodex-masters.vercel.app/sites/:path*/assets/:file*` (static-media proxy; activates fully once `sites/{id}/assets/` moves out of the main deploy).
- All other rewrites are API catch-all routing (scholars, creatives, slots, bookings, patrons, account, admin, v1, v2, search, analytics, crawler, cron, webhook, root `/api/:slug*`).
- Headers: `must-revalidate` on `/(.*\.html)`, `/`, and `/sites/(.*)/` (269–276); immutable 1y on `/css`, `/js`, `/assets`.

## 7. Non-flagship clean URLs today
- `punicodex.com/marduk/` → middleware step 8: `marduk` not in ARCHETYPE_IDS → `fetch(request)` → Vercel static → no `/marduk/` file → **404** (slashless `/marduk` first 308s to `/marduk/` via `trailingSlash:true`).
- `/sites/marduk/` → served directly from the static file `sites/marduk/index.html` (base temple, generated by generate-temples.js).
- **Slug-collision check for a site-wide `/{id}/` scheme**: `sites/` has 973 dirs; zero overlap with any root directory or reserved path (api, assets, css, js, data, docs, store, blog, search, type, ...). 7 stale dirs not in the lexicon: `achilles, delphi, europa, hercules, jason, khaos, pegasus` (legacy aliases — decide: delete or add to LEGACY_REDIRECTS). All 966 lexicon ids have a dir.

## 8. Search page
- `/search/index.html`: canonical → `https://punicodex.com/search/` (line 12), **no noindex**, query read client-side from `?q=`.
- **Crawlable `?q=` links**: every base temple embeds `<a href="https://punicodex.com/search/?q={domain-or-punycode}">` (685+ matches, e.g. `sites/adad/index.html:221`; emitted by `scripts/generate-temples.js`). These parameterized URLs are a major contributor to the 778 "alternative page with proper canonical" — they consolidate correctly to `/search/` but burn crawl budget. Options: keep as-is (canonical handles it), strip the href to plain `/search/`, or add `noindex,follow` to the search page.
