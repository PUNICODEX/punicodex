# PUNICODEX — Agent Reference

This file is the entry point for AI coding agents working on this repository.
It describes what the project is, how it is built, tested, and deployed, and
which conventions must not be broken. Everything below reflects the repository
as it actually exists (data version `2.0.63`, July 2026).

---

## Project Overview

PuniCodex is a multi-platform product built around **Unicode (IDN) domain
names** — domains containing accented/non-ASCII characters (e.g. `apóllōn.com`,
punycode `xn--aplln-1ta64d.com`). It combines:

- **A scholarly lexicon** of 895 mythological/linguistic name restorations
  across 22 pantheons (Greek, Norse, Egyptian, Hindu, Japanese, and more),
  each with character breakdowns, original scripts, pronunciation data,
  etymology, and citations (LSJ, Beekes, Faulkner, …).
- **895 static "temple" pages** at `/sites/{id}/` — one per lexicon entry.
  196 of these are hand-crafted **flagship** temples for owned domains; the
  rest are generated **base** temples.
- **A search engine for the Unicode web**: a crawler that indexes live `xn--`
  domains, plus an availability layer with registrar affiliate links.
- **A domain-leasing platform**: flagship domains are leasable "real estate"
  with ad slots, bookings, tenants, patron tiers, and analytics (see
  `platform/VISION.md`).
- **An Authenticity / brand-protection subsystem**: ML-assisted homograph and
  confusable detection (name authenticity checker, threat feeds, policy
  engine, benchmarks, red-team CI), exposed via API, browser extension, and
  SDKs.
- **A Scholarly Edition**: university-sponsored, peer-reviewed scholarly
  sections layered onto flagship temples (`/sites/{id}/scholars/`).
- **An AI training-corpus pipeline** that exports the lexicon as JSONL
  datasets (pretrain, instruction, safety, reasoning, tool-use, multimodal,
  oracle, benchmarks) with a data card and model card.
- **Client apps**: a type-tool website, two browser extensions, a mobile PWA,
  a Capacitor Android app, an Electron desktop browser, and SDKs for JS, iOS,
  Android, Flutter, React Native, embedded, wearables, and WordPress.

The whole project is held together by a **generation flywheel**: a small set
of canonical, hand-edited sources from which every consumer (websites,
extensions, mobile, Android, middleware, cards, corpora) is regenerated by
`npm run generate`. Never edit generated outputs by hand.

## Tech Stack at a Glance

- **Runtime**: Node.js (>= 20; CI uses 22), CommonJS modules, no TypeScript,
  no frontend framework — static HTML/CSS/vanilla JS pages.
- **Hosting**: Vercel (static site + serverless functions in `api/` + edge
  `middleware.js`). Crons configured in `vercel.json`.
- **Local platform server**: Express 5 (`platform/server.js`,
  `npm run platform` → http://localhost:3456).
- **Databases**: SQLite via `better-sqlite3` (local + ephemeral `/tmp` on
  Vercel); optional Postgres (`postgres`, `@neondatabase/serverless`);
  optional Redis (`ioredis`) for rate limiting.
- **Key dependencies**: `cheerio` (crawler HTML parsing), `bcrypt` (auth),
  `stripe` (payments), `@xenova/transformers` (ML embeddings/classifiers),
  `unicode-name`, `canvas`, `jimp`, `image-size`, `cors`.
- **Tooling**: Biome 2.5 (format + lint), `c8` (coverage), Capacitor 8
  (Android), Electron + electron-builder (desktop browser), Playwright-core,
  ffmpeg-static.
- **Tests**: plain Node test files + `node --test`, orchestrated by
  `test/run-all.js` (136 suites). No Jest/Mocha.

## Critical File Guardrails

### `vercel.json` — NEVER append duplicate keys
`vercel.json` must remain valid JSON with exactly one instance of each
top-level key. A previous batch script accidentally appended a second
`redirects` array after `rewrites`, creating invalid duplicate keys that broke
Vercel routing for `punicodex.com/{id}` paths. **Always validate JSON
structure after any automated modification.** If regenerating `vercel.json`,
overwrite the entire file — never append.

Today `vercel.json` legitimately contains:
- `trailingSlash`, `functions` (function bundles include `platform/db/**`),
- `rewrites` — **API rewrites only** (`/api/v1/scholars/*`, `/api/v1/creatives/*`,
  `/api/slots/*`, `/api/bookings/*`),
- `crons` — 8 scheduled jobs (crawler, discover, verify-availability,
  process-queue, process-events, trial-reminders, lease-expiry,
  sponsorship-expiry),
- `headers` — security headers + cache-control rules.

### `middleware.js` — Domain routing source of truth
All **domain** redirects and path rewrites (Unicode/punycode deity domains →
`/sites/{id}`) are handled by `middleware.js`. Its `DOMAIN_MAP` block is
GENERATED by `scripts/sync-middleware-domains.js` from `js/archetypes-v2.js` —
do not hand-edit inside the generated markers. Do NOT add domain `redirects`
or `rewrites` to `vercel.json` unless explicitly migrating routing out of the
middleware.

### `ACCURACY.md` — Authoritative accuracy standard
All changes to lexicon entries, original scripts, character breakdowns, and
generated temples must follow `ACCURACY.md`. It defines the source hierarchy,
original-script verification procedure, punycode validation rules, and the
deployment checklist. Consult it before adding or editing any entry.

## The Generation Flywheel

PUNICODEX is a multi-platform product: website, individual temples, type tool,
search engine, lexicon, APIs, browser extensions, mobile app, Android app,
desktop browser, and AI corpora. To keep all of these in sync, the project
uses **canonical sources** and **generated outputs**.

### Canonical sources (edit these by hand)

- `type/js/lexicon.js` — The 895-entry lexicon. Single source of truth for
  all lexicon data.
- `type/js/original-scripts.js` — Curated original-script mappings and
  provenance for non-Greek/CJK traditions (plus
  `type/js/original-scripts-extra.json`).
- `type/js/source-catalog.js` — Rich citation metadata for scholarly reference
  works (182 entries).
- `type/js/pronunciation-atlas.js` — Pronunciation data (873 entries).
- `type/js/glyph-atlas.js` — Glyph render data (672 entries).
- `js/archetypes-v2.js` — Hand-built flagship archetypes (196), including
  domain ownership and canvas assignments.
- `platform/db/owned-domains.json` — The complete list of 206 owned Unicode
  domain strings. Every entry here must be covered by an archetype domain set
  and routed in `middleware.js`.
- `scripts/lore-catalog.json` — Rich scholarly narrative content for the 196
  built flagship entries (pronunciation, mythology, archaeology, sources,
  cultural legacy).
- `platform/blog/content/{id}.json` — One canonical blog post per built
  flagship temple (196 files). Generated by
  `scripts/generate-blog-content.js`; edit only the JSON if a post needs
  correction, then rerun the generator.
- `platform/public/scholars/` — Canonical source for the Scholarly Edition
  portal pages (root `scholars/` is generated).
- `platform/public/admin-portal/` — Canonical source for the unified admin
  portal pages (root `admin-portal/` is generated by
  `scripts/sync-admin-portal.js`).
- `platform/scholars/content/{id}.json` — Per-temple scholarly content
  (bootstrapped fill-only-missing, then treated as canonical).
- `docs/scholarly-edition/scholarly-section-taxonomy-v0.1.json` — Scholars
  section registry.

### Generated outputs (DO NOT edit by hand)

Produced by `npm run generate`. They contain header comments or sidecar

- `extension/shared/lexicon.js`, `mobile/shared/lexicon.js`
- `android/app/src/main/assets/shared/lexicon.json` and `keyboard-palette.json`
- `platform/browser/renderer/lexicon.json` (+ `similarities.json`,
  `lore-catalog.json`)
- `platform/api/similarities.json`, `platform/api/cards.json`,
  `game/cards.json`
- `js/owned-entries.js`
- `middleware.js` (`DOMAIN_MAP` block)
- `sites/{id}/` base temples; flagship temples are regenerated each run by
  `scripts/create-flagship.js --regenerate-all`
- Lore-catalog copies for extension/mobile/type
- `platform/scholars/taxonomy-data.js`, `platform/scholars/manifests/{id}.json`,
  `sites/{id}/scholars/index.html`

  `platform/public/admin-portal/` (by `scripts/sync-admin-portal.js`)
- `data/corpus/*` AI datasets, `data-version.json`, DataCite metadata

### Workflow

1. Edit the canonical source.
2. Run `npm run generate`.
3. Run `npm test`.
4. Commit both the source and the regenerated files.

CI enforces this with a **divergence gate**: after tests pass, it runs
`npm run generate` and fails if any generated file differs from what is
committed (`git diff --exit-code`). If the gate fails, you forgot to run
`npm run generate` after changing a canonical source. `npm run generate:check`
and the `prepush` script (`npm test && npm run generate:check`) check this
locally.

### Analytics & Search Console

- Set `GA_MEASUREMENT_ID` (e.g., `G-XXXXXXXXXX`) and `GSC_VERIFICATION` as
  environment variables before running `npm run generate`.
- `scripts/inject-analytics.js` injects the first-party analytics beacon
  (`/js/analytics-beacon.js`) into every public HTML page, plus the GA4
  snippet and Google Search Console verification meta tag when the env vars
  are set.
- The beacon tag is always injected; GA4/GSC tags appear only with the env
  vars set. Injection is idempotent (strip-then-inject between the
  PUNICODEX-ANALYTICS markers).

### Flywheel Integrity Validator

`scripts/validate-flywheel.js` is part of `npm test`. It proves the canonical
sources and all generated consumers are internally consistent:

- Archetype ids, names, and Greek originals match the lexicon.
- `middleware.js` `DOMAIN_MAP` routes every archetype domain (Unicode, Punycode,
  and `www.` variants) to `/sites/{id}`.
- `middleware.js` `ARCHETYPE_IDS` derives exactly from the archetype list.
- Every owned domain in `platform/db/owned-domains.json` is covered by an
  archetype domain set and routed in middleware.
- Generated lexicon copies derive byte-identically from the canonical lexicon.
- `platform/browser/renderer/lexicon.json` entries, breakdowns, pantheon list,
  and `hasFlagship` set derive exactly from the canonical lexicon and archetype
  list.
- Every lexicon entry has a temple page at `sites/{id}/index.html`.
- Flagship HTML pages are checked for placeholder text, required meta/OG tags,
  canonical links, displayed Unicode name, Greek original (Greek entries),
  primary domain, tier badge, and mascot/logomark asset references. Current
  inconsistencies are reported as warnings.

If this validator fails, run `npm run generate` and fix any remaining source
mismatches it reports.

### Scholarly Edition

The Scholarly Edition is a university-edited scholarly layer for the 196
flagship temples. It lives at `/sites/{id}/scholars/` and is managed through
the `/api/v1/scholars/` API.

**Canonical / hand-edited:**
- `docs/scholarly-edition/scholarly-section-taxonomy-v0.1.json` — section registry
- `docs/scholarly-edition/GOVERNANCE.md` — editorial rules
- `docs/scholarly-edition/ARCHITECTURE.md` — technical blueprint
- `platform/scholars/content/{id}.json` — per-temple scholarly content
  (markdown bodies + sources per section). Bootstrapped by
  `scripts/generate-scholars-content.js` (fill-only-missing: it synthesizes
  missing sections from lore-catalog/lexicon/archetypes/original-scripts/
  source-catalog/similarities and never overwrites a non-empty body), then
  treated as canonical — hand edits survive regeneration.

**Generated (do not edit by hand):**
- `platform/scholars/manifests/{id}.json` — per-temple section manifests
  (blank taxonomy structure with the content files merged in as published
  sections)
- `platform/scholars/taxonomy-data.js` — JS copy of the canonical taxonomy
  registry (by `scripts/generate-scholars-taxonomy.js`); required because
  Vercel function bundles do not include runtime JSON/fs reads, so the API
  loads the taxonomy through this module. Excluded from biome formatting.
- `sites/{id}/scholars/index.html` — Scholarly Edition pages

**Database:**
- `platform/db/migrate-scholars.js` — core Scholars schema
- `platform/db/migrate-scholars-quality.js` — quality gate column
- Seed with `node platform/db/scholars/seed.js` — publishes manifest content
  under the "PuniCodex Team" identity (curator account with an unguessable
  random password hash) with full edit-history attribution; never overwrites
  a section whose body is non-empty. `api/v1/scholars.js` runs the same seed
  on every cold start so the ephemeral Vercel DB serves real content.
- Migrate lore-catalog content with `node scripts/migrate-lore-to-scholars.js`

**Key pages (under `/scholars/`):** `login`, `apply` (public sponsorship
application), `dashboard` (student submissions), `review` (reviewer queue),
`admin` (curator admin), `institution` (university dashboard + analytics),
`dept-admin` (department-scoped student management for the `dept_admin`
role), `search`, `analytics`.

**Portal sync direction:** `platform/public/scholars/` is the CANONICAL source
for the portal pages; `scholars/` at the repo root is GENERATED by
`scripts/sync-scholars-portal.js` (part of `npm run generate`) which deletes
and re-copies the directory. Edit `platform/public/scholars/` only.

**Access model & hardening (2026-07):**
- University-sponsorship model: curators approve applications
  (`POST /api/v1/scholars/sponsorship/applications/:id/approve` provisions the
  institution + admin with a one-time temp password); institution admins
  provision/revoke student credentials.
- Revocation is immediate: password change/reset and account disable destroy
  the account's sessions (`deleteSessionsForUser`); `requireAuth` rejects
  non-active accounts on the next request.
- Sponsorship expiry is enforced at read time in
  `platform/scholars/authz.js#isActiveSponsorship`; the
  `/api/cron/sponsorship-expiry` cron (daily) flips the stored status.
- Scholars rate limiting is Redis-backed when `REDIS_URL` is set (prefix
  `punicodex:rl:scholars:{tier}:...`), in-memory otherwise.
- `api/v1/scholars.js` runs the scholars + quality migrations on cold start
  (idempotent), matching the creatives handler, and then seeds the ephemeral
  database from the generated manifests (`seedScholarsFromManifests`).
- Department admins (`dept_admin`) manage students in their own department
  only: the student-management endpoints under `/api/v1/scholars/institution/*`
  accept `requireDepartmentAdmin`, scope dept_admin callers to their own
  department (`resolveDepartmentScope` + `canManageStudent`), and keep
  reviewer promotion, institution analytics, and allowlist management
  institution-admin-only. UI at `/scholars/dept-admin/`.
- Provisioning emails are wired through `platform/api/email.js`
  (`notifyScholarsAccountProvisioned`): sponsorship approval, student
  creation, and student password resets email the one-time temp password and
  login URL to the recipient (fire-and-forget; the no-`RESEND_API_KEY`
  console fallback remains). Temp passwords are still shown to the acting
  curator/admin exactly once as a fallback channel.
- Known limitations: SQLite on Vercel `/tmp` is ephemeral (production
  persistence needs an external DB).

### Data versioning

`data-version.json` is the machine-readable dataset manifest. It is
regenerated by `npm run generate` and exposed via `GET /api/v1/version`.

The manifest includes:

- `version` — semantic data version (`major.minor.patch`, currently `2.0.63`)
- `releasedAt` — ISO timestamp of the last `npm run generate`
- `canonicalSources` — map of canonical source roles to file paths
- `canonicalHashes` — SHA-256 hashes of each canonical source
- `counts` — entries (895), pantheons (22), flagships (196), original scripts
  (108), source-catalog entries (182), pronunciation atlas (873), glyph atlas
  (672)
- `schema` — numeric major/minor/patch
- `license` — SPDX id + URL

Versioning rules:

- **Major** — backwards-incompatible schema or mass-removal of entries (manual).
- **Minor** — new pantheons, new flagship domains, or large content additions (manual).
- **Patch** — auto-incremented by `scripts/update-data-version.js` whenever any
  canonical source hash changes between runs.

When you edit a canonical source, run `npm run generate` so the patch version
and hashes stay in sync with the committed files. CI treats
`data-version.json` as a generated artifact.

### DOI pipeline

`scripts/generate-datacite-doi-metadata.js` produces a DataCite-compatible XML
metadata file from `data-version.json`. The script does **not** register a
DOI; it generates the deposit payload for DataCite or Zenodo. Registration
must be done manually or via a repository webhook once a license is chosen.

### Data licensing

The PuniCodex dataset is released under **CC BY 4.0** (see root `LICENSE`).
The software code remains under the license declared in `package.json`
(currently ISC) unless otherwise noted in individual files.

To keep `data-version.json` and the DataCite metadata XML in sync, set these
environment variables before running `npm run generate`:

```bash
export PUNICODEX_LICENSE=CC-BY-4.0
export PUNICODEX_LICENSE_URL=https://creativecommons.org/licenses/by/4.0/
```

If the license ever changes, `scripts/update-data-version.js` will detect the
change and bump the data-version patch automatically.

### Safe-edit scripts

Use these instead of hand-editing multiple canonical files:

- `node scripts/add-owned-domain.js <id> <domain>` — appends an owned domain to
  `platform/db/owned-domains.json`, injects it into the matching archetype's
  domain set, regenerates derived artifacts, and validates.
- `node scripts/promote-to-flagship.js <id> [--domain <domain>]` — marks a
  lexicon entry as a flagship, creates/updates its archetype entry, optionally
  wires an owned domain, runs `create-flagship.js`, regenerates derived
  artifacts, and validates.

`scripts/sync-mobile-lexicon.js` is **deprecated** and will exit with an
error; `mobile/shared/lexicon.js` is now a full copy of the canonical lexicon.

### Authoritative import framework

Publicly available scholarly datasets (Wikidata, Perseus/LSJ, Cologne
Sanskrit, CDLI, Rundata, etc.) are imported through `data/authoritative/`.

**Governance rule: canonical sources are still king.** Importers are not
allowed to mutate canonical sources directly. They produce reviewed suggestion
batches that are applied with `scripts/apply-suggestions.js`.

Directory layout:

- `data/authoritative/importers/{source}.js` — one Node module per upstream source
- `data/authoritative/source-tiers.json` — authority tier ranking for the merge cascade
- `data/authoritative/snapshots/{source}/{runId}.json` — raw upstream responses
- `data/authoritative/staging/suggestions/{source}/{runId}.json` — per-source normalized suggestions
- `data/authoritative/staging/merged/{runId}.json` — multi-source merged batch
- `data/authoritative/staging/merged/{runId}-conflicts.json` — same-tier conflicts for review
- `data/authoritative/staging/applied/{source}-{runId}.json` — audit log of applied batches

Workflow:

1. **Run an importer**: `node scripts/import-runner.js {source} [--run-id {id}] [--dry-run]`
2. **Run the multi-source orchestrator**: `node scripts/import-orchestrator.js [--run-id {id}]`
   (higher-tier suggestions override lower-tier; same-tier conflicts go to the conflicts file)
3. **Inspect**: `node scripts/import-runner.js {source} --dry-run`
4. **Apply reviewed suggestions**: `node scripts/apply-suggestions.js data/authoritative/staging/merged/{runId}.json`
   (suggestions with `confidence < 0.5` are skipped automatically)
5. **Regenerate and test**: `npm run generate && npm test`

Only these suggestion fields are currently auto-applied: `meaning`, `greek`,
`domain`, `sourceCatalog`, `originalScript`. More complex fields (`etymology`,
`variant`, `lore`) are flagged for manual review.

Every suggestion must carry a `provenance` object with `source`,
`retrievedAt`, `url`, and `license`. Upstream data more restrictive than CC BY
4.0 must be reviewed before inclusion.

## Testing Strategy

`npm test` runs `test/run-all.js`, which executes **136 suites** sequentially

## The Definitive Tier System (CANONICAL)

### Dual-Tier Names (3 total)
**Apollo, Hekate, Nike**

A name is dual-tier **if and only if** all of the following are true:
- The Greek original contains **BOTH** stress (acute/circumflex) **AND** at
  least one long vowel (η, ω, long α/ι/υ, or long diphthong)
- There are **MULTIPLE** historically valid Unicode spellings (alternate
  stress positions, alternate long-vowel interpretations, dialectal variation)
- The ASCII fallback is **ALSO** historically legitimate (not merely modern English)
- You **own** the domain variants
- Each variant corresponds to a **real, attested, alternate restoration**

These temples **must** display two meta-badges (**Tier-1** + **Tier-2**), two
name cards or an explicit dual-tier explanation, and footer **Dual-Tier Pair
(Tier-1 & Tier-2)**.

**Owned domains:** `apóllōn.com` + `apollōn.com`, `hekate.com` +
`hekátē.com`, `nike.com` + `níkē.com`.

### Single-Tier Tier-1 Names (13 total)
**Zeus, Árēs, Aphrodítē, Athénā, Dēmētēr, Hēra, Hermês, Hēphaistos, Hestía,
Poseidôn, Persephonē, Promētheus, Hádēs**

A name is single-tier Tier-1 **if and only if**: the Greek original contains
both stress and a long vowel; there is only one historically valid Unicode
restoration; the ASCII fallback is not ancient canonical; and you do not own
multiple canonical variants representing distinct spellings.

These temples display one **Tier-1** meta-badge, one Unicode Restoration
card, footer **Tier-1**, and explanatory text citing that the Greek original
has both stress and length.

### Single-Tier Tier-2 Names
**Ártemis, Átlas, Diónysos, Médousa, Óðinn, Þórr, Kēr, etc.**

The Greek original contains only one feature (stress OR long vowel) or
neither. Temples display one **Tier-2** meta-badge (with subtype label if
applicable, e.g., "Accent-Preserving" or "Macron-Preserving"), one Unicode
Restoration card, footer **Tier-2**, and text citing which single feature is
preserved.

### Key Distinction

| Property | Dual-Tier (3) | Single-Tier Tier-1 (13) | Single-Tier Tier-2 |
|----------|--------------|------------------------|--------------------|
| Greek has both stress + length | ✔ | ✔ | ✘ |
| Multiple valid Unicode spellings | ✔ | ✘ | N/A |
| ASCII fallback is ancient canonical | ✔ | ✘ | varies |
| Owns multiple domain variants | ✔ | ✘ | varies |
| Layout | Two badges, dual footer | One badge, single footer | One badge, single footer |

**Never flatten the Big Three. Never dual-tier the single-tier names.**

## Multi-Form System (Evolved Convention)

A name may have **multiple valid Unicode restorations**. The lexicon stores
all attested forms; the temple displays them with explanation.

### Fallback Hierarchy (Domain Selection)

| Priority | Form | Example | When to Use |
|----------|------|---------|-------------|
| 1 | **Full restoration** (all marks) | `Aphrodítē` | Ideal. Use when domain is available. |
| 2 | **Circumflex** (stress + length in one char) | `Hermês`, `Poseidôn` | Greek has circumflex AND the domain is available. Typeable on phones. |
| 3 | **Macron-only** (standard academia) | `Hēra`, `Persephonē` | Default fallback. LSJ convention. Always defensible. |
| 4 | **Variant form** (attested alternate) | `Athēnā` (Ἀθηνᾶ) | Canonical form changes the final letter and would hurt recognizability. |
| 5 | **Plain ASCII** | `Hera` | Last resort. Never primary. |

### Rules

- **Macron-only is not wrong.** It is the standard convention in
  Liddell-Scott-Jones, Cambridge, and Oxford texts.
- **Combined marks** (e.g., `ḗ`) are philologically ideal but often untypeable
  on phones and may be unavailable as domains.
- **Wrong accent position is worse than no accent.** `ápollōn` was scrapped in
  favor of plain `apollōn`.
- **Recognizability matters.** Now that `athénā.com` is acquired, it is the
  primary for Athena.

### Name Variations Sections

Every flagship temple **must** include a "Name Variations" section showing
the **owned form** (primary badge), the **ideal form** (with availability
status), and the **ASCII form** — each with the Unicode, the Greek mapping,
and why the form is used.

### Variant Sources and Type Tool Display

Variant objects in the lexicon may carry an optional `sources` array. The
type tool separates variants into:

1. **Derived Forms** — `owned`, `ideal`, `macron-only`, `ascii`. Always shown
   as copyable chips.
2. **Scholarly Variants** — `alt-stress`, `alt`. **Only shown when the
   variant carries a `sources` array.**

The lexicon validator warns (does not fail) when an `alt-stress`/`alt`
variant lacks sources. When adding a scholarly variant, always cite the
supporting source(s).

## Platform, Search Engine & APIs

PUNICODEX is a **search engine for the Unicode web**, not a registrar.

### Architecture

```
User Query → Lexicon Filter → Results Engine
                              ├── Live Site → Business Card (title, desc, snippet)
                              └── No Site   → Availability + Registrar Links
```

### Database

SQLite at `platform/db/punicodex.db` (local) / `/tmp` on Vercel. `npm run
db-init` runs `platform/db/init.js` plus 34 migrations (crawler, booking v1–4
+ status, trial columns, operational tables, AI columns, entity mentions, API

### Crawler Flow

1. **Discovery**: domain submitted (manual, bulk, or CT-log scan)
2. **Normalize**: punycode + Unicode display form
3. **Match lexicon**: link by punycode, unicode, or ASCII core
4. **Fetch**: HTTP(S) with 10s timeout, follow redirects
5. **Extract**: title, meta description, og:description, h1, first `<p>`
6. **Store**: upsert into `indexed_sites` with content-hash dedup

## Security Considerations

- API keys are stored as **SHA-256 hashes only**; plaintext shown once at
  creation. Admin sessions use bearer tokens (`x-admin-token`).
- Passwords hashed with **bcrypt**; session revocation is immediate on
  password change/reset/disable (`deleteSessionsForUser`). The unified admin
  portal adds per-user `admin_users` accounts (roles, lockout) — see
  `platform/api/admin-portal-auth.js`.
- Security headers on every route via `vercel.json`; strict referrer policy,
  HSTS, Permissions-Policy, and a report-only CSP (soak before enforcing).
- Webfonts are **self-hosted**: all pages load `/assets/fonts/fonts.css`
  (committed, built once from Google Fonts on 2026-07-18; woff2 binaries in
  `assets/fonts/`, unicode-range splitting preserved). Never re-add
  `fonts.googleapis.com` / `fonts.gstatic.com` links or preconnects — the CSP
  drops those hosts; regression suite: `test/fonts-selfhosted.test.js`.
- Rate limiting on public APIs and Scholars (Redis when `REDIS_URL` set);
  public write endpoints (crawl events, gamification, agents, workspace) are
  all rate-limited. The 2026-07 security audit lives at
  `docs/security/security-audit-2026-07.md` (regression suite:
  `test/security-hardening.test.js`).
- Homograph/confusable defenses are a first-class feature with adversarial
  and red-team testing; telemetry-privacy and retention suites guard data
  handling.
- `docs/security/cve-tracker.md`, `docs/standards/` (ISO 27001 / SOC 2
  mappings, ICANN SSAC, W3C WebAppSec, Unicode ICU submissions) track
  compliance work; runbooks in `docs/runbooks/` cover incident response.
- Do not commit secrets; env vars in use include `GA_MEASUREMENT_ID`,
  `GSC_VERIFICATION`, `REDIS_URL`, `PUNICODEX_LICENSE(_URL)`, admin tokens,
  Stripe keys.
