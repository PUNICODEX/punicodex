# PUNICODEX — Agent Reference

Entry point for AI coding agents: what the project is, how it is built, tested, deployed, and which conventions must not be broken.

## Project Overview

PuniCodex is a multi-platform product built around **Unicode (IDN) domain names** (e.g. `apóllōn.com`, punycode `xn--aplln-1ta64d.com`): a scholarly lexicon (980 mythological name restorations, 25 pantheons); **980 temple pages** at `/sites/{id}/` (542 hand-crafted **flagship** temples + 438 generated **base** temples); a **search engine for the Unicode web** (crawler indexes live `xn--` domains); a **domain-leasing platform** (ad slots, bookings, patrons, analytics — `platform/VISION.md`); **authenticity/brand protection** (homograph/confusable detection via API, extension, SDKs); the **Scholarly Edition** + **AI corpus pipeline**; and **clients**: type-tool site, two browser extensions, mobile PWA, Android app, Electron browser, SDKs for 8 platforms.

Everything is held together by a **generation flywheel**: canonical, hand-edited sources from which every consumer is regenerated by `npm run generate`. **Never edit generated outputs by hand.**## Tech Stack

Node.js >= 20 (CI 22), CommonJS, no TypeScript, no framework — static HTML/CSS/vanilla JS. Local server: Express 5 (`npm run platform` → :3456). Vercel hosting (static + serverless `api/` + edge `middleware.js`). SQLite (`better-sqlite3`; local + ephemeral `/tmp` on Vercel); optional Postgres; Redis rate limiting. Tooling: Biome 2.5, `c8`, Capacitor 8, Electron. Tests: plain Node + `node --test` via `test/run-all.js` (232+ suites).

## Critical File Guardrails

### `vercel.json` — NEVER append duplicate keys
`vercel.json` must remain valid JSON with exactly one instance of each top-level key. A previous batch script appended a second `redirects` array after `rewrites`, breaking Vercel routing for `punicodex.com/{id}` paths. **Always validate JSON structure after any automated modification.** If regenerating, overwrite the entire file — never append.

Today it legitimately contains: `trailingSlash`; `functions` (bundles include `platform/db/**`); `rewrites` (**API rewrites only**); `crons`; `headers` (security + cache-control).

### `middleware.js` — Domain routing source of truth
All **domain** redirects/rewrites (Unicode/punycode deity domains → `/sites/{id}`) live in `middleware.js`. Its `DOMAIN_MAP` / `LEXICON_IDS` / `LEGACY_REDIRECTS` blocks are GENERATED by `scripts/sync-middleware-domains.js` (the legacy-redirect table itself is a hand-edited constant at the top of that script) — do not hand-edit inside the generated markers. Do NOT add domain `redirects`/`rewrites` to `vercel.json` unless explicitly migrating routing out of the middleware.

The clean `/{id}/*` form is the canonical temple URL: middleware rewrites `/{id}/*` → `/sites/{id}/*` for all `LEXICON_IDS`, and 301s legacy `/sites/{id}/*` page requests to the clean form — EXCEPT `/sites/{id}/assets/*`, which passes through untouched (the vercel.json static-media proxy depends on the `/sites/` prefix).

### `ACCURACY.md` — Authoritative accuracy standard
All changes to lexicon entries, original scripts, character breakdowns, and generated temples must follow `ACCURACY.md` (source hierarchy, original-script verification, punycode validation, deployment checklist). Consult it before adding or editing any entry.

### Workflow

1. Edit the canonical source. 2. `npm run generate`. 3. `npm test`. 4. Commit source + regenerated files together.

CI enforces a **divergence gate**: after tests pass it runs `npm run generate` and fails if any generated file differs. Local checks: `npm run generate:check`, `npm run prepush`. **Analytics:** set `GA_MEASUREMENT_ID` + `GSC_VERIFICATION` before generate — `scripts/inject-analytics.js` injects GA4 + GSC alongside the first-party beacon; idempotent.

`scripts/validate-flywheel.js` (part of `npm test`) proves canonical/generated consistency: archetypes match the lexicon; `DOMAIN_MAP` routes every archetype domain (Unicode, punycode, `www.`) and every owned domain; lexicon copies byte-identical; every entry has a temple page. On failure: `npm run generate`, then fix mismatches.

### Flagship completeness gate + gallery doctrine (HARD RULES)

`validate-flywheel.js` hard-fails any **built flagship** missing: lore-catalog entry, `rentalTier`, bespoke hero effect (`templates/flagship/effects/effects.json`), curated gallery (≥2 images in `scripts/gallery-data.json` **or** an `_honestZero` exemption), ≥3 industry-pattern seats, and a **domain form matching the canonical restoration** (legitimate deviations need a reasoned entry in `DOMAIN_FORM_EXCEPTIONS` in the validator). `promote-to-flagship.js` prints the same checklist with remedies after every promotion.

Gallery images come ONLY from `scripts/curate-gallery-images.js` (`--only <ids>`): word-boundary topicality, junk-signal lists, and the Commons **category gate** reject modern people/places/brands (location temples exempt from place-noise rules). Audit with `--verify` / `--verify --cats`; `--purge` strips. Never add an unfiltered Commons fetcher — `batch-new-flagships.js` delegates to the curator; `fetch-missing-galleries.js` is deprecated. Figures with genuinely no Commons coverage go in `_honestZero` rather than shipping unrelated images.

### Master generator

`scripts/generate.js` runs 46 scripts in dependency order. Order constraints that must not break: WebP conversion MUST follow flagship temples; model corpus → `entries.jsonl` MUST precede the AI corpora and RE-RUNS last so `manifest.json` converges; pronunciation corpus MUST follow model corpus; desktop nav and temple index are canonical — never fork; the three injectors (analytics, university, mobile menu) RE-RUN after store pages, idempotently.

## Data versioning, DOI, licensing

`data-version.json` — generated manifest (version now `2.0.108`), exposed via `GET /api/v1/version`. **major**/**minor** bumps are manual; **patch** auto-increments on any canonical hash change (`scripts/update-data-version.js`). ### Authoritative import framework

Public scholarly datasets (Wikidata, Perseus/LSJ, CDLI, Rundata, …) import through `data/authoritative/` — importers never mutate canonical sources; they produce reviewed suggestion batches applied with `scripts/apply-suggestions.js`. ## Testing Strategy

`npm test` runs `test/run-all.js`: **232+ suites** sequentially (most 30s timeout; heavy up to 30min), plain Node + `node --test`. Groups: data integrity (Lexicon Validator 74k+ assertions, engine, generated artifacts, Divergence Gate); SEO/links/accuracy (Link Checker, Philological Accuracy, Flywheel Integrity, Lighthouse 90+); API & services; Scholars; Authenticity (red-team, FP/FN budgets); Clients; AI corpus.

**Rule:** after any canonical-source change, `npm run generate && npm test` must pass before committing. Never mark work done while suites are red.

### Pre-push gate (installed hook)

A git `pre-push` hook (installed by `scripts/install-hooks.js` via `npm prepare`) runs `scripts/prepush-gate.js` before every push. It diffs the commits being pushed, maps changed files to the suites that can actually break (suite commands parsed from `test/run-all.js` at runtime — `--self-test` validates the mapping), and runs those plus the always-on Format Check + Biome Lint. Canonical-source changes additionally run the divergence gate. A red gate blocks the push — fix locally instead of discovering it in CI. Escape hatches: `git push --no-verify` (you own the red CI), `PREPUSH_FULL=1` to force the full battery, `PREPUSH_FILES="..."` to simulate. When adding suites to `test/run-all.js`, extend `RULES` in `scripts/prepush-gate.js` if the new suite guards a distinct area.

## Deployment (Vercel)

Static pages + `api/**/*.js` serverless functions (bundles include `platform/db/**` so SQLite migrations/seed run on cold start).

### Deploy routes (since 2026-08-01)

- **Standard — CI prebuilt** (`.github/workflows/deploy-prebuilt.yml`): automatic on master push once CI's full battery passes (`vercel pull` → `build` → `deploy --prebuilt --archive=tgz` → aliases). **Never run `--prebuilt` from Windows** — traced native binaries are win32 and the Lambdas die. Secrets: `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`. **Do not also run a local CLI deploy of the same commits** — a failed battery means no deploy, by design.
- **Fallback — local CLI**: `vercel deploy --prod --yes --archive=tgz` (archive mandatory — tree exceeds the 15,000-file upload limit), then alias manually. Local deploys bundle the gitignored `platform/db/punicodex.db` as the seed DB.

### Function architecture (28 routed functions)

Most endpoints are served by catch-all routers (`api/[[...slug]].js`, `api/admin/`, `api/v1/`, `api/v2/`, `api/search/`, `api/analytics/`, `api/crawler/`) whose handlers live in `platform/api-handlers/{admin,v1,v2,search,analytics,crawler,root}/`; routers lazy-require only the matched handler. Hard-won contracts (guarded by `test/vercel-config.test.js` + API suites): each catch-all needs an explicit `vercel.json` rewrite to its literal bracket path with `:slug*` capture (routers read `req.query.slug`, which arrives as one slash-joined string they split); router tables carry a `segments: []` alias for the bare parent path; real files always win over catch-alls; escape-hatch rewrites protect `/api/cron/*` and `/api/webhook/*` from the root router.

### Platform facts

- `vercel.json`: security headers on all routes, `must-revalidate` on HTML/SW, immutable 1-year caching on `/css`, `/js`, `/assets`; static-media proxy `/sites/:id/assets/*` → `punycodex-masters.vercel.app`; cron jobs.
- Temple media (mascots/logomarks/videos) served from `punycodex-masters.vercel.app` (gitignored `.masters/`, deployed from inside it).
- **CSS/JS edits must always ship with a `?v=` version bump** — immutable-cached for a year.
- SQLite on Vercel `/tmp` is **ephemeral**; **Postgres is the production operational store** when `DATABASE_URL` is set (it is, all environments) — `platform/db/operational.js` persists bookings, analytics, discount codes, patrons, portal.
- **Creatives persist to Vercel Blob** when `BLOB_READ_WRITE_TOKEN` is set; otherwise local (dev) / `/tmp` (bare Vercel) via `/api/uploads/[[...slug]]`. Display layers resolve both via `resolveCreativeUrl`.
- `REDIS_URL` → globally consistent Redis rate limits; otherwise in-memory.
- Root `sw.js` must **never intercept `/api/` or `/admin-portal/`**, and every `respondWith` path must resolve to a real `Response`. Bump the cache revision on any fix (`test/service-worker.test.js`).

### Original Script Display

The legacy `greek` field is reliable only for Greek, Devanagari, CJK; elsewhere it may be `"—"` or a transliteration. Canonical: `type/js/original-scripts.js` + `-extra.json`; generators resolve via `getOriginalScript(entry)`. ## The Definitive Tier System (CANONICAL)

### Dual-Tier (3 total): Apollo, Hekate, Nike

Dual-tier **iff all of**: Greek original has BOTH stress (acute/circumflex) AND a long vowel (η, ω, long α/ι/υ, or long diphthong); MULTIPLE historically valid, attested Unicode spellings exist; both are live as owned domain temples (a display fact, never a criterion). Display: two meta-badges, two name cards, footer **Dual-Tier Pair (Tier-1 & Tier-2)**. Owned: `apóllōn.com` + `apollōn.com`, `hekate.com` + `hekátē.com`, `nike.com` + `níkē.com`.

### Single-Tier Tier-1 (mechanical rule, since 2026-07-20)

**Iff** mechanically verifiable as information-rich — no editorial judgment: **Greek** — original has BOTH stress AND ≥1 long vowel (a circumflex counts as both); **all other traditions** — the restoration preserves ≥1 distinctive feature ASCII loses: **any** preserved diacritic (detected structurally by NFD decomposition, never a hand-enumerated list) **or** a distinctive atomic letter (þ/ð/æ/œ/š/ḍ/ṭ/ḥ/ṛ/ꜣ/ꜥ, ǫ, …).

Reference: `tools/new-domains/reclassify-tiers.js`; no exceptions beyond reviewed orthographic edge cases (currently only `asia`). **Ownership, prominence, and ASCII-canonicity are display facts, never tier criteria.**

### Single-Tier Tier-2

Greek original has only one feature (stress OR length) or neither; non-Greek preserves nothing distinctive vs ASCII. Dual-tier shows two badges + dual footer; single-tier shows one.

**Never flatten the Big Three. Never dual-tier the single-tier names.**

## Multi-Form System

A name may have multiple valid restorations; the lexicon stores all attested forms, temples display them with explanation.

### Fallback Hierarchy (Domain Selection)

| Priority | Form | Example | When |
|----------|------|---------|------|
| 1 | Full restoration | `Aphrodítē` | Ideal |
| 2 | Circumflex (stress+length) | `Hermês`, `Poseidôn` | Greek has circumflex; phone-typeable |
| 3 | Macron-only (LSJ) | `Hēra`, `Persephonē` | Default fallback, always defensible |
| 4 | Variant (attested) | `Athēnā` (Ἀθηνᾶ) | Canonical form would hurt recognizability |
| 5 | Plain ASCII | `Hera` | Last resort, never primary |

Rules: **macron-only is not wrong** (LSJ/Cambridge/Oxford convention); combined marks (`ḗ`) are ideal but often untypeable/unavailable; **wrong accent position is worse than none**; **canonical beats recognizability when both are owned** (`athēnâ.com` is Athena's primary). Every flagship needs a **Name Variations** section (owned / ideal / ASCII, with Greek mapping + why). The type tool shows Scholarly Variants **only when the variant carries `sources`**.

## Platform, Search Engine & APIs

A **search engine for the Unicode web**, not a registrar. Flow: query → lexicon filter → results (live site → business card; no site → availability + registrar links).

- **DB:** SQLite `platform/db/punicodex.db` (local) / `/tmp` (Vercel); `npm run db-init` = `init.js` + migrations. Core tables: `entries`, `breakdowns`, `entries_fts` (FTS5), `indexed_sites`, `availability`, `api_keys` (SHA-256 only), `admin_sessions`.
- **Crawler:** discovery (manual/bulk/CT-log) → normalize → match lexicon → fetch (10s) → extract (title, meta, og, h1, first `<p>`) → upsert with content-hash dedup.
- **Public API:** `search`, `entry/:id`, `stats`, `crawl` (+`/bulk`, `/recrawl`), `sites` (+`/search`, `/:punycode/spam`), `crawler/stats`, `availability/:entryId`, `slots`, `bookings`, `glyph`, `oracle`, `pantheons`, `marketplace`, `agents`, `analytics`, `flagships`, `verify`, `submit`, `webhook`, `health`, `protocol`, and more (see routers).
- **`/api/v1`:** `names` (+ variants, breakdown, original-script, etymology, availability, site, slots, pronunciation), `pantheons`, `tiers`, `autocomplete`, `convert` (+`/batch`), `appraise`, `authenticity`, `threat-feed`, `policy`, `canary`, `transparency-report`, `similarities`, `industry-patterns` (+`/industries`, `/match`), `connections`, `cards`, `creatives`, `scholars`, `version`, `docs`, `openapi.json`. **`/api/v2`:** `search`, `names`, `sites`, `pantheons`, `tiers`, `convert`, `autocomplete`, `health`, `version`, `openapi.json`.
- **Appraisal (`appraise-3.0.0`):** meaning + demand only (attestation, tier, development, industry demand). No brand multiplier; **no ASCII comparison for Unicode names** (`asciiControlValue`/`premiumMultiplier`/`discount` = `null`). Trademark proximity = suppression only (≤0.5). Verdict-only by default; `?explain=1` for breakdown. Docs `docs/appraisal-methodology.md`; `test/appraise.test.js`.
- **Admin:** `x-admin-token`; API keys under `/api/admin/api-keys`. **Unified admin portal:** per-user `admin_users` (bcrypt, roles `superadmin/ops/leasing/scholars/viewer`, lockout, immediate revocation); frontend `/admin-portal/` (canonical `platform/public/admin-portal/`). Bootstrap: empty `admin_users` + `ADMIN_PASSWORD` → one superadmin.
- **Patrons:** `GET /api/patrons/:templeId` (public), `POST /api/patrons/checkout` (Stripe); `checkout.session.completed` activates via `api/webhook/`.
- **Auth & limits:** `Authorization: Bearer <key>`; keyless reads at free tier. Per-day: Free 100, Hobby 1,000, Pro 10,000, Enterprise 100,000.
- **Ranking:** `is_flagship DESC` → `tier='dual' DESC` → `tier='1' DESC` → `unicode ASC`. **Registrars:** GoDaddy, Namecheap, Porkbun, Dynadot, Spaceship.
- **Unicode constraint:** only ~8% of discovered domains are actual `xn--` — compensated by a +0.5 xn-- ranking bonus and a 'Unicode Only' filter.

## Security Considerations

- API keys stored as **SHA-256 hashes only**; admin sessions use bearer tokens (`x-admin-token`). Passwords bcrypt-hashed; revocation immediate on change/reset/disable (`deleteSessionsForUser`). Admin portal: per-user `admin_users` (roles, lockout) — `platform/api/admin-portal-auth.js`.
- Security headers on every route via `vercel.json`; HSTS, Permissions-Policy, report-only CSP (soak before enforcing).
- Webfonts are **self-hosted** (`/assets/fonts/`). **Never re-add `fonts.googleapis.com` / `fonts.gstatic.com` links or preconnects** (`test/fonts-selfhosted.test.js`).
- Rate limiting on public APIs and Scholars (Redis when `REDIS_URL` set); all public write endpoints rate-limited. 2026-07 audit: `docs/security/security-audit-2026-07.md` (`test/security-hardening.test.js`).
- Homograph/confusable defenses are first-class, adversarial + red-team tested; telemetry-privacy and retention suites guard data handling.
- Do not commit secrets; env vars: `GA_MEASUREMENT_ID`, `GSC_VERIFICATION`, `REDIS_URL`, `PUNICODEX_LICENSE(_URL)`, admin tokens, Stripe keys.
